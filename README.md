# yapus

> If an AI writes the code, what keeps it sound?

**The foundation for building software with AI.** yapus is the core of how an AI coding agent is run: the rules that keep the work sound and maintainable, and the mechanisms that hold them.

Requires Node 24 or newer, bash 3.2 or newer, git 2.42 or newer and Claude Code 2.1.295 or newer; `npm test` also requires ShellCheck 0.11.0.

`git config core.hooksPath hooks/git`, run once in a clone, makes git refuse a commit whose subject is not `type(scope): verb ...` with each word listed in `hooks/shared/catalogs/`; for an agent it also adds the yapus trailers to each commit and refuses a new branch not named `<type>/<slug>`. `git config --unset core.hooksPath` undoes it.

`claude plugin install providens --marketplace bug3/yapus`, run once, installs the orchestrator plugin providens: it puts the orchestration rules (ORCH-1 to 7) at the start of every session while it is on, provides seven subagents (`providens:builder`, `reader`, `plan-reviewer`, `diff-reviewer`, `runner`, `web-researcher`, `mcp-operator`) and the skill `/providens:write-plan` for writing the plan of deep work before its first edit, limits subagent launches and the size of what returns to the main session, and checks the form of `gh pr create` and `gh issue create` calls: the title, the labels, the body headings and the footer by the catalogs of the repository the call runs in (`hooks/shared/catalogs/`), and only the body headings in a repository without them. `claude plugin uninstall providens@yapus` undoes it.

providens counts the subagent launches of a session and refuses the one past the budget: 41, or the whole number `/providens:agent-limit <n>` sets for the session, or with `--global` for every session, in the plugin's data directory (`CLAUDE_PLUGIN_DATA`, under `~/.claude/plugins/data/`). It writes every launch verdict, every launch's end (duration, tokens, tool calls, whether the subagent ran out of turns), every resume of a subagent and every return verdict (with the transcript's turns, tokens, tool calls and wall time) as one JSON line to `decisions.jsonl` in the same directory; the record never leaves the machine. `/providens:agent-report` prints the record's counts per agent and the reading rules with their state (act, wait or ok). The gh check knows the options of gh 2.102 and refuses an option it does not know.

`/providens:switch off` turns providens off for the session, or with `--global` for every session: no rules at the session's start and no check on its launches; `/providens:switch on` turns it back on, and `/providens:status` shows the mode and the limit in force and the session's launches.

`claude plugin install landmark --marketplace bug3/yapus`, run once, installs the standards plugin landmark. `/landmark:install`, run once, puts the yapus standards and git hooks into `~/.claude` for the machine; `/landmark:upgrade` brings them up to the plugin's version.

In a session opened at the root of a git repository, `/landmark:project` writes the yapus repository setup into it: the ESLint and TypeScript base under `.claude/yapus/landmark/`, the root `eslint.config.ts` and `tsconfig.json` that build on it, the `check` and `test` scripts, the pinned devDependencies and `"type": "module"` in `package.json`, the workflow `.github/workflows/yapus.yml` and the scope catalog `.claude/yapus/landmark/scopes.json`; it removes the old ESLint config files and packages. In a repository that carries its stamp (`.claude/yapus/landmark/version`), the same command upgrades only yapus's own files to the plugin's version; the root files, `scripts.test` and the scope catalog belong to the project. The command writes nothing while a path it would write or remove has an uncommitted change, and never runs `npm`; it prints the next steps and the git steps that undo it. With the argument `go`, in a repository whose root holds `go.mod`, it writes the golangci-lint config `.golangci.yml`, the workflow and the scope catalog instead, records the language in `.claude/yapus/landmark/language` for the upgrade and never runs golangci-lint; it prints the pinned golangci-lint install and the Go checks as next steps.
