# yapus

> If an AI writes the code, what keeps it sound?

**The foundation for building software with AI.** yapus is the core of how an AI coding agent is run: the rules that keep the work sound and maintainable, and the mechanisms that hold them.

Requires Node 24 or newer, bash 3.2 or newer, git 2.42 or newer and Claude Code 2.1.295 or newer; `npm test` also requires ShellCheck 0.11.0.

`git config core.hooksPath hooks/git`, run once in a clone, makes git refuse a commit whose subject is not `type(scope): verb ...` with each word listed in `hooks/shared/catalogs/`; for an agent it also adds the yapus trailers to each commit and refuses a new branch not named `<type>/<slug>`. `git config --unset core.hooksPath` undoes it.

`claude plugin install delegator --marketplace bug3/yapus`, run once, installs the orchestrator plugin delegator: it puts the orchestration rules (ORCH-1 to 7) at the start of every session while it is on, provides nine subagents (`delegator:builder`, `reader`, `plan-writer`, `plan-reviewer`, `finisher`, `diff-reviewer`, `runner`, `web-researcher`, `mcp-operator`) and the skill `/delegator:write-plan` for having the plan of deep work written before its first edit, limits subagent launches and the size of what returns to the main session, and checks the form of `gh pr create` and `gh issue create` calls: the title, the labels, the body headings and the footer by the catalogs of the repository the call runs in (`hooks/shared/catalogs/`), and only the body headings in a repository without them. `claude plugin uninstall delegator@yapus` undoes it.

delegator counts the subagent launches of a session and refuses the one past the budget: 41, or the whole number `/delegator:agent-limit <n>` sets for the session, or with `--global` for every session, in the plugin's data directory (`CLAUDE_PLUGIN_DATA`, under `~/.claude/plugins/data/`). It writes every launch verdict, every launch's end (duration, tokens, tool calls, whether the subagent ran out of turns), every resume of a subagent and every return verdict (with the transcript's turns, tokens, tool calls and wall time) as one JSON line to `decisions.jsonl` in the same directory; the record never leaves the machine. `/delegator:agent-report` prints the record's counts per agent and the reading rules with their state (act, wait or ok). The gh check knows the options of gh 2.102 and refuses an option it does not know.

delegator writes each prompt the person types, with its time, as one JSON line to `.yapus/prompts/<session id>.jsonl` under the directory the session opened in, and right after a compaction it gives the session those prompts back, the newest that fit in 6,000 characters, with the paths of the five newest plans in `.yapus/plans/`. It creates the prompts directory readable by its owner alone and with a `.gitignore` that keeps it out of git; a person who wants their prompts in git changes that file. A prompt that cannot be written is not kept and is never blocked.

For deep work `delegator:plan-writer` writes the plan to `.yapus/plans/<topic>.md`, and one `delegator:finisher` per slice edits, runs the slice's oracle, has `delegator:diff-reviewer` judge the diff, commits the slice and returns the commit, the oracle's exit code, the verdict and the path of the detail file `.yapus/plans/<topic>/<slice id>.md`, which holds the rest. The finisher is the one subagent that launches another, the diff reviewer alone, and it never pushes.

`/delegator:switch off` turns delegator off for the session, or with `--global` for every session: no rules at the session's start, no check on its launches, and no prompt written or given back; `/delegator:switch on` turns it back on, and `/delegator:status` shows the mode and the limit in force and the session's launches.

`claude plugin install ordo --marketplace bug3/yapus`, run once, installs the standards plugin ordo. `/ordo:machine`, run once, puts the yapus standards and git hooks into `~/.claude` for the machine; `/ordo:upgrade` brings them up to the plugin's version.

In a session opened at the root of a git repository, `/ordo:repo` writes the yapus repository setup into it: the ESLint and TypeScript base under `.claude/yapus/ordo/`, the root `eslint.config.ts` and `tsconfig.json` that build on it, the `check` and `test` scripts, the pinned devDependencies and `"type": "module"` in `package.json`, the workflow `.github/workflows/yapus.yml` and the scope catalog `.claude/yapus/ordo/scopes.json`; it removes the old ESLint config files and packages. In a repository that carries its stamp (`.claude/yapus/ordo/version`), the same command upgrades only yapus's own files to the plugin's version; the root files, `scripts.test` and the scope catalog belong to the project. The command writes nothing while a path it would write or remove has an uncommitted change, and never runs `npm`; it prints the next steps and the git steps that undo it. With the argument `go`, in a repository whose root holds `go.mod`, it writes the golangci-lint config `.golangci.yml`, the workflow and the scope catalog instead, records the language in `.claude/yapus/ordo/language` for the upgrade and never runs golangci-lint; it prints the pinned golangci-lint install and the Go checks as next steps.
